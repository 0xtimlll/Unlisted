# Ревью Unlisted: с чего начать

Короткая карта для того, кто смотрит проект впервые: что это, как запустить, где что лежит,
что сделано намеренно и где известные слабые места. Подробности по каждому протоколу — в
[README](../README.md), правила проекта — в [CLAUDE.md](../CLAUDE.md).

## Что это

Некастодиальный мост в виде статического сайта (Next.js static export на Cloudflare Pages, только
desktop). Своих контрактов и бэкенда нет: страница читает контракт моста, собирает транзакцию и
отдаёт её в кошелёк. Четыре вкладки: OFT (LayerZero V2 и v1, включая Solana), Wormhole NTT,
Chainlink CCIP и Status / Rescue для застрявших сообщений LayerZero.

Сайт: <https://oft-bridge-ui.pages.dev>. Он закрыт паролем (HTTP Basic Auth, см. раздел
«Site password» в README), пароль даёт владелец.

## Запуск

```sh
npm ci                 # ignore-scripts включён: зависимости ничего не исполняют при установке
npm run dev            # http://localhost:3000, вкладки на /bridge, /ntt, /ccip, /rescue
npm test               # белый список write-примитивов + юнит-тесты (869 тестов, 39 файлов)
npm run typecheck
npm run lint
npm run build          # out/ + заголовки безопасности; CI делает то же самое
npm run test:integration   # живые публичные RPC и форк на anvil; бывает флейки, в npm test не входит
```

## Главное решение, которое легко принять за ошибку

**Сервис информирует, решает человек.** Это решение владельца от 2026-09-30, оно намеренное.

- **Кнопка держится только когда транзакция невозможна.** Нет кошелька или не та сеть, не хватает
  токена или газа, нет маршрута, сумма после округления нулевая, адрес получателя нельзя
  закодировать для сети назначения. Причина — одна серая строка под кнопкой.
- **Всё остальное — цвет индикатора, а не запрет.** Нулевой адрес, получатель-контракт моста,
  двойник адреса из книги, peer без обратной ссылки, мёртвый DVN — красный. Свежий адаптер, один
  RPC, упавшая симуляция — жёлтый. Отправка при этом возможна.
- **Галочек нет.** Единственное подтверждение — ввод последних 6 символов нового адреса получателя.

Если при ревью кажется, что что-то «должно блокировать», сначала проверьте, физически ли
невозможна транзакция. Если нет, это вопрос к владельцу, а не баг.

## Что не должно ослабнуть никогда

Это инварианты сборки транзакции. Любое их ослабление — настоящая находка.

| Инвариант | Где держится |
|---|---|
| calldata только через `abi + functionName + args`, никакого `sendTransaction` | `scripts/check-whitelist.mjs` (часть `npm test`) |
| approve ровно на сумму; исключение — approve(0) перед approve(сумма) для токенов вроде USDT | `src/core/approveFlow.ts`, guard'ы 10–12 |
| spender — проверенный контракт маршрута, не ввод пользователя и не ответ API | `approvePlan` в каждом протоколе + сверка в `onApprove` каждой вкладки |
| никакого approve при `approvalRequired === false` | guard 11 |
| `refundAddress` = подключённый кошелёк | guard 1 (`plan.sender == wallet`) |
| получатель закодирован так, как его прочтёт сеть назначения | self-check: `core/guards.selfCheck`, `lz-v1/selfcheck.ts`, `core/svm` |
| guard'ы перепроверяются в момент клика | `onApprove` / `onSend` каждой вкладки, тест в `severityGate.test.ts` |

## Что известно и сознательно не сделано

Всё записано в [docs/TODO.md](TODO.md) с причиной и тем, что нужно, чтобы закрыть. Коротко:

- locking-хаб NTT всегда красный, даже настоящий с залоченной долей;
- красная строка про двойника адреса не называет запись из книги;
- в форме v1 переключение на чужой адрес сделано чекбоксом, а не ссылкой «Edit»;
- декодер legacy type-2 adapter params строже релеера;
- стандарт v1 `bytes` не проверен ни на одном живом контракте.

## Что проверено и что нет

- **Проверено:** юнит-тесты, белый список, lint, typecheck, сборка — зелёные; CI на `main` зелёный.
  Сценарий CT (Ethereum → BNB Chain, 25 CT) пройден в Chromium со стаб-кошельком: зелёный индикатор,
  кнопка «Approve exactly 25 CT», в кошелёк уходит `approve(адаптер, 25e18)`, после receipt кнопка
  становится Send.
- **Не проверено автоматически:** настоящие подписанные транзакции в сети. Их владелец проверяет
  руками. Форк-тесты на anvil (`tests/integration/fork.test.ts`) исполняют реальные approve и send,
  но запускаются только при установленном Foundry.

## Как прислать правки

Удобнее всего списком: файл и строка, что не так, как воспроизвести, насколько серьёзно. Отдельно
отметьте всё, что касается инвариантов из таблицы выше: это приоритет №1.
